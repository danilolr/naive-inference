Implementation Guide

How naive-inference is built, module by module, with excerpts and links to every source file. Assumes you can read Python; LLM concepts are explained in the Concepts page (referenced as §C throughout). The normative spec is docs/SPEC.md; the plain-text walkthrough is docs/IMPLEMENTATION.md. Sections follow its reading order.

1. Design rules

  • Python + NumPy, optional CUDA via CuPy. No torch, no transformers, no compiled extensions in the engine. Dependencies: NumPy + regex (CuPy only for the CUDA backend). The server uses the stdlib http.server — no web framework.
  • One code path. Every module reads arrays.xp at call time; it is bound to NumPy (CPU) or CuPy (CUDA) at startup. The same math runs from a laptop to a DGX Spark (§15).
  • Learning-first. Readable vectorized NumPy beats fast opaque code. Shape errors raise (programmer errors). Comments explain why.
  • Functional ops, in-place states. Vector ops return new arrays (idiomatic NumPy; the matmul dominates, elementwise ops are memory-bound). Recurrent states are preallocated and updated in place.
  • Memory-aware weights. bf16 on disk as uint16; converted once to fp32 when the model fits the device budget, else converted per matmul — on CPU as zero-copy mmap views (§5, §13).
  • Config-driven. Every dimension comes from config.json; the same code runs 4B and 27B (proven in M5).
  • Oracle-verified, separation enforced. Every milestone compares against HF (§14). test_no_oracle_deps.py fails if any engine module imports torch/transformers/tokenizers.

2. arrays.py — one code path, two backends

arrays.py

The whole engine is written once against arrays.xp, a NumPy-compatible namespace. select_backend rebinds it at startup; every module does from . import arrays and reads arrays.xp inside functions, so import order never matters and switching backends needs no code changes: 

# Active namespace and backend name. Rebound by select_backend().
xp = np
backend = "cpu"

def select_backend(prefer: str = "auto", verbose: bool = False) -> str:
    global xp, backend
    want_cuda = prefer == "cuda" or (prefer == "auto" and cuda_available())
    if want_cuda:
        # ... raise if CuPy is missing or no CUDA device is visible ...
        xp, backend = cp, "cuda"
    else:
        xp, backend = np, "cpu"
    return backend

bf16 has no native dtype in NumPy/CuPy, so weights are uint16 bit patterns. A bf16 value is exactly the top 16 bits of an fp32 value — conversion is a vectorized shift + reinterpret, identical on both backends (§C8): 

def bf16_to_fp32(u16):
    return (u16.astype(xp.uint32) << 16).view(xp.float32)   # lossless

to_device / to_cpu cross the host/device boundary (no-ops on CPU). free_memory() reports the placement budget: free VRAM on CUDA, MemAvailable from /proc/meminfo on CPU. fp32_to_bf16 (round-to-nearest-even) exists only for tests and synthetic fixtures — the engine never writes bf16.

Pitfalls #15 / #16
Never call .astype(float32) on a uint16 array — that interprets the integer value, not the bit pattern. And never do from arrays import xp at import time: the namespace is rebound by select_backend, so a stale binding would silently keep using NumPy.

3. safetensors.py — zero-copy loading

safetensors.py tests

File layout (SPEC §9):

┌──────────────┬─────────────────────────┬──────────────────────────┐
│ u64 header N │ N bytes JSON header     │ raw tensor blob          │
│ (LE)         │ name → {dtype, shape,   │ (bf16 / f32, row-major)  │

File.open mmaps a shard read-only and parses the JSON header (skipping __metadata__). Tensors are memoryview slices into the mapping; as_uint16() wraps them as NumPy arrays with no copy. Store.open_dir resolves names across shards via model.safetensors.index.json (2 shards for 4B, 18 for 27B). The OS page cache manages residency — nothing is read until touched, so a 55 GB checkpoint loads instantly. This module is host-only; device placement happens later (§5). 

mm = mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ)
raw = memoryview(mm)
header_len = struct.unpack("<Q", raw[:8])[0]
meta = json.loads(bytes(raw[8:8 + header_len]))

def as_uint16(self) -> np.ndarray:
    """Interpret a 2-D BF16 tensor as a [rows, cols] uint16 view (no copy)."""
    # ... dtype/shape checks ...
    return np.frombuffer(self.data, dtype="<u2").reshape(self.shape[0], self.shape[1])
Not everything is bf16
The precision-sensitive linear-attention vectors linear_attn.A_log and linear_attn.norm.weight are stored F32 in the real checkpoints (dt_bias is BF16). Tiny 1-D vectors are converted to fp32 eagerly via as_fp32_vec(), which handles both dtypes; matrices stay uint16 until placement.

Lifecycle (pitfall #17): NumPy views export the mmap, so Store.close() clears its tensor views first and tolerates a BufferError if live views remain — callers drop weights before closing (Model.close() does exactly that).

4. config.py — config-driven dimensions

config.py tests

Dataclasses mirror config.json (the text_config subtree). Derived helpers are methods, never constants — no model-specific numbers in the layer code, so the same code runs 4B and 27B: 

# methods of TextConfig
def key_dim(self) -> int:
    return self.linear_num_key_heads * self.linear_key_head_dim

def value_dim(self) -> int:
    return self.linear_num_value_heads * self.linear_value_head_dim

def conv_dim(self) -> int:
    return 2 * self.key_dim() + self.value_dim()

def gva_ratio(self) -> int:
    return self.linear_num_value_heads // self.linear_num_key_heads

def rotary_dim(self) -> int:
    return int(self.head_dim * self.rope.partial_rotary_factor)   # 64 of 256

validate() rejects unsupported architectures and broken invariants up front: model_type == qwen3_5, layer_types length matches num_hidden_layers, GQA and GVA head divisibility, hidden_act == silu, mamba_ssm_dtype == float32, rope_type == default. The layer list comes from text_config.layer_types — never hardcoded.

5. weights.py — resolution and placement

weights.py model.py · _choose_placement

load_weights resolves every text-model tensor as a host view (full name list in SPEC §9.2). Rules: ignore mtp.* and model.visual.*; tied embeddings (4B: no lm_head.weight → reuse embed_tokens; 27B: separate tensor); conv weight [conv_dim, 1, 4] squeezed to 2-D; norm vectors fp32 at load (they are tiny). 

w.lm_head = w.embed if cfg.tied_embeddings() else _mat(store, "lm_head.weight")

LinearWeight wraps a matrix that is either fp32 (converted once) or uint16 bf16 (converted per call). linear() is the hot path — \(y = x \cdot W^\top\) because nn.Linear weights are [out, in]. BLAS on CPU, cuBLAS on CUDA; decode is a matrix–vector product: 

class LinearWeight:           # arr is fp32 [out,in] or uint16 bf16 [out,in]
    def fp32(self):
        if self.is_bf16:
            return arrays.bf16_to_fp32(self.arr)
        return self.arr

def linear(x, w: LinearWeight):
    """y = x @ W^T. x: [n, in] or [in]; returns [n, out] or [out]."""
    wf = w.fp32()
    if x.ndim == 1:
        return wf @ x
    return x @ wf.T

matrix_bytes totals the bf16 footprint; model._choose_placement picks (backend, dtype) from the budget, then materialize moves weights to the device — converting to fp32 once if that regime was chosen: 

for m in _iter_matrices(w):
    dev = arrays.to_device(m.arr)  # uint16 on device (no-op view on CPU)
    if dtype == "fp32":
        m.arr = arrays.bf16_to_fp32(dev)
        m.is_bf16 = False
    else:
        m.arr = dev
        m.is_bf16 = True
bf16_bytes = total weight matrix bytes (uint16)
fp32_bytes = 2 * bf16_bytes
budget     = 0.9 * free_memory()      # VRAM on CUDA, MemAvailable on CPU

if CUDA available and (device == "cuda" or device == "auto"):
    if fp32_bytes <= budget:  -> cuda, fp32   (fastest: convert once, cuBLAS)
    elif bf16_bytes <= budget:-> cuda, bf16   (convert per matmul)
    elif device == "cuda":    -> raise (use -device cpu)
    else:                     -> fall back to CPU
CPU:
    if fp32_bytes <= budget:  -> cpu, fp32    (materialize in RAM, BLAS)
    else:                     -> cpu, bf16    (zero-copy mmap, page cache)

Every decision is logged at load ([placement] cpu, weights fp32 — fp32 in RAM). Embedding lookup converts only the requested rows, never the whole vocab matrix. Full guide: docs/HARDWARE.md.

6. ops.py — vector primitives

ops.py tests

Functional, fp32, backend-agnostic — one function per formula from §C3–§C6. The two RMSNorm variants are the most error-prone part (SPEC §4, pitfalls #1/#3). Read them side by side: 

def rms_norm(x, w, eps: float):
    """Zero-centered Qwen3_5 RMSNorm: out = x * rsqrt(mean(x^2) + eps) * (1 + w)."""
    xp = arrays.xp
    ms = xp.mean(x * x, axis=-1, keepdims=True)
    inv = 1.0 / xp.sqrt(ms + eps)
    return x * inv * (1.0 + w)

def rms_norm_gated(x, w, gate, eps: float):
    """Gated norm of the linear-attention output, per value head (SPEC §4.2)."""
    xp = arrays.xp
    ms = xp.mean(x * x, axis=-1, keepdims=True)
    inv = 1.0 / xp.sqrt(ms + eps)
    return x * inv * w * silu(gate)
(1 + w) vs plain w
rms_norm is zero-centered: weights init to 0 and the scale is (1 + w) — using plain w (LLaMA style) silently zeroes everything. It is used by input/post-attention norms, the final norm, and per-head q/k norms. rms_norm_gated uses plain w (init ones) and applies norm BEFORE the silu(gate) multiply — it is the linear-attention output norm, per 128-dim value head. Do not mix them up.

apply_rope rotates only the leading 2*len(inv_freq) dims (partial RoPE, rotate_half layout — pairs are \((x_i, x_{i+32})\), not adjacent elements). Angles are formed in fp32, cos/sin evaluated in fp64 and cast back, matching the reference numerics: 

half = int(inv_freq.shape[0])
rot = 2 * half
x1 = x[..., :half]
x2 = x[..., half:rot]
angle = (xp.asarray(pos, dtype=xp.float32) * inv_freq).astype(xp.float64)
cos = xp.cos(angle).astype(xp.float32)
sin = xp.sin(angle).astype(xp.float32)
out = x.copy()
out[..., :half] = x1 * cos - x2 * sin
out[..., half:rot] = x2 * cos + x1 * sin
return out

Also: softmax (max-subtraction, fp32), l2norm (SUM, not mean — pitfall #6), softplus (linear above 20, matching torch), sigmoid, silu, inv_frequencies (\(\theta^{-2i/d}\), \(\theta = 10^7\)).

8. forward.py — the layer math

forward.py tests (prefill ≡ decode)

Full attention (every 4th layer)

Implements §C4 exactly, batched over the sequence, each step traceable:

  1. ln1_out — zero-centered RMSNorm over hidden.
  2. q_raw/k_raw/v_raw — projections; q is double-width.
  3. Split per head: first half → query, second half → gate; q_norm/k_norm per head.
  4. q_rot/k_rot — partial RoPE at position past + t.
  5. Append post-RoPE k and raw v to the KV cache (pitfall #11).
  6. GQA: query head hh uses KV head hh // groups; causal mask j <= past + t; scores × \(256^{-0.5}\); fp32 softmax.
  7. sigmoid output gate multiply, then o_proj, residual add.
  8. Shared forward_mlp: ln2 → gate/up → silu·mul → down → residual.
# Double-width q: per head, first half query, second half gate (pitfall #2).
qr = q_raw.reshape(seq, heads, 2 * hd)
q = ops.rms_norm(qr[..., :hd], aw.q_norm, eps)        # [seq, heads, hd]
gate = qr[..., hd:].reshape(seq, heads * hd)          # [seq, heads*hd]
k = ops.rms_norm(k_raw.reshape(seq, kv_heads, hd), aw.k_norm, eps)
# GQA with causal masking, softmax in fp32 (pitfall #12).
for hh in range(heads):
    kvh = hh // groups
    scores = (q[:, hh, :] @ k_src[:, kvh, :].T) * scale  # [seq, kv_len]
    scores = xp.where(mask, scores, xp.float32(-xp.inf))
    probs = ops.softmax(scores, axis=-1)
    attn_out[:, hh, :] = probs @ v_src[:, kvh, :]

# Output gate: sigmoid, NOT swish (pitfall #3).
gate_sig = ops.sigmoid(gate)
attn_flat = attn_flat * gate_sig

Linear attention — Gated DeltaNet, the heart

One code path for prefill and decode (SPEC §6.4): the recurrence is position-implicit, and the conv shift register starting from zeros reproduces prefill's zero left-padding. Projections are batched over the sequence; the conv and the recurrence step token by token. The depthwise conv keeps pre-activation inputs and applies SiLU inside the conv step (pitfalls #5/#8): 

for t in range(seq):
    win[:, :-1] = win[:, 1:]      # shift left
    win[:, -1] = qkv_all[t]       # append new pre-activation input
    conv_out[t] = xp.sum(win * conv_w, axis=1)  # depthwise dot product
    mixed[t] = ops.silu(conv_out[t])
# beta = sigmoid(b); g = -exp(A_log) * softplus(a + dt_bias), fp32 (pitfall #7).
beta = ops.sigmoid(b_all)                                   # [seq, nv]
g_decay = -xp.exp(lin.a_log) * ops.softplus(a_all + lin.dt_bias)

GVA expands q/k from 16 key heads to all value heads via repeat_interleave (consecutive v-heads share a k-head — pitfall #13), then L2 norm (SUM!) and the \(1/\sqrt{128}\) scale on q only (pitfall #6): 

q = xp.repeat(q, ratio, axis=1)  # [seq, nv, kd]
k = xp.repeat(k, ratio, axis=1)
q_normed = ops.l2norm(q, 1e-6) * q_scale
k_normed = ops.l2norm(k, 1e-6)

Then the delta rule itself (§C6): fp32 state S [nv, kd, vd], token loop, vectorized over heads with einsum: 

for t in range(seq):
    decay = xp.exp(g_decay[t])                 # [nv]
    s *= decay[:, None, None]                  # decay whole state
    k_t, q_t, v_t = k_normed[t], q_normed[t], v[t]
    kv_mem = xp.einsum("hkv,hk->hv", s, k_t)   # what state already predicts
    delta = (v_t - kv_mem) * beta[t][:, None]  # correction
    s += xp.einsum("hk,hv->hkv", k_t, delta)   # write correction
    core_out[t] = xp.einsum("hkv,hk->hv", s, q_t)  # read UPDATED state

Followed by per-head rms_norm_gated with gate z (plain w, silu gate), out_proj, residual, shared MLP. The trace captures both final states — which is how M2 proved the recurrence ≡ the model's chunked prefill formulation (~1e-5).

Order matters
decay → read kᵀS → delta → outer-product write → output. The output reads the state after the current token's write (pitfall #9). q/k L2-norm happens after GVA repeat-interleave, in fp32, before the \(1/\sqrt{128}\) scale.

10. tokenizer/ — text ↔ ids

tokenizer.py pretokenize.py bpe.py bytelevel.py chat.py golden tests

The pretokenizer: official regex, verbatim

Python's regex module supports \p{...} and lookahead (the stdlib re does not), so the official Qwen pattern from tokenizer_config.json is used verbatim — no hand-written scanner needed: 

PATTERN = regex.compile(
    r"(?i:'s|'t|'re|'ve|'m|'ll|'d)"
    r"|[^\r\n\p{L}\p{N}]?[\p{L}\p{M}]+"
    r"|\p{N}"
    r"| ?[^\s\p{L}\p{M}\p{N}]+[\r\n]*"
    r"|\s*[\r\n]+"
    r"|\s+(?!\S)"
    r"|\s+"
)

def pretokenize(s: str) -> list[str]:
    return [m.group(0) for m in PATTERN.finditer(s)]

BPE and byte tables

bpe.py: naive loop — find the lowest-rank adjacent pair, merge all its occurrences left-to-right, repeat. O(n²) and proud of it. bytelevel.py rebuilds the GPT-2 table algorithmically (printable bytes map to themselves; the rest get code points from U+0100). 

while True:
    best_rank = None
    best_pair = None
    for i in range(len(symbols) - 1):
        pair = (symbols[i], symbols[i + 1])
        rank = ranks.get(pair)
        if rank is not None and (best_rank is None or rank < best_rank):
            best_rank, best_pair = rank, pair
    if best_pair is None:
        break
    # ... merge ALL occurrences of best_pair left-to-right, then loop ...

encode: split added (special) tokens literally, longest first → NFC on the gaps (stdlib unicodedata) → pretokenize → byte-encode → BPE → vocab lookup. No BOS is prepended. decode_bytes returns raw bytes, which is what makes UTF-8-safe incremental streaming possible. 

normalized = unicodedata.normalize("NFC", seg)
for pretok in pretokenize(normalized):
    for piece in bpe(byte_encode(pretok), self.ranks):
        tid = self.vocab.get(piece)
        if tid is None:
            raise ValueError(f"piece {piece!r} not in vocab")
        ids.append(tid)

Chat template, effort, streaming

chat.py renders the text-only ChatML subset. The generation prompt opens a think block; disabled thinking pre-fills it empty so the model answers directly. Assistant history turns get _strip_thinking (keep everything after the last closing think tag). Validated against HF apply_chat_template goldens. 

if opts.add_generation_prompt:
    parts.append(f"<|im_start|>assistant\n{THINK_OPEN}\n")
    if not opts.enable_thinking:
        parts.append(f"\n{THINK_CLOSE}\n\n")

def _strip_thinking(content: str) -> str:
    """Keep everything after the LAST closing think tag (official logic)."""
    idx = content.rfind(THINK_CLOSE)
    if idx >= 0:
        return content[idx + len(THINK_CLOSE):].lstrip("\n")
    return content

Reasoning effort (Qwen3.8): reasoning_effort ∈ {xhigh (default), medium, low} injects a verbatim instruction from the official chat_template.jinja into the system turn — prepended to an existing system message, or becoming one when none exists. medium injects nothing; thinking-off ignores the field entirely; other values raise. It is prompt conditioning, not a token budget. The 4B template predates effort (its goldens use medium).

UTF-8 subtlety: byte-level pieces can split a rune across tokens ("Ol" + "á"-as-bytes). The chat CLI uses an incremental UTF-8 decoder (codecs.getincrementaldecoder); the server decodes all ids so far and trims an incomplete trailing rune — no replacement-character flicker.

        try:
            return b.decode("utf-8")
        except UnicodeDecodeError:
            b = b[:-1]
    return ""

def emit(dr, dc):                    # SSE delta for /v1/chat/completions
    d = {}
    if dr:
        d["reasoning_content"] = dr
    if dc:
        d["content"] = dc
    chunk(d)
Two subtleties
Think splitting: the think OPEN tag lives in the prompt (template), so generated reasoning arrives without it — _split_think takes an in_think flag from the request, and _trailing_partial withholds trailing incomplete tags so streaming never emits half a tag. Concurrency: generation is CPU/GPU-bound, so a threading.Lock serializes it (concurrent requests queue); weights and tokenizer are read-only and shared safely.

13. Numerics policy (SPEC §2)

  • Weights: bf16 on disk, stored as little-endian uint16. Conversion is the vectorized shift (u16 << 16).view(fp32) — lossless, identical on NumPy and CuPy. Two regimes from the memory budget: fp32 weights (converted once at load, fastest matmul) when the model fits; bf16 weights (converted inside each linear() call, half the memory) otherwise. On CPU, bf16 keeps the mmap advantage.
  • Activations: fp32 everywhere, on both backends — simpler and more accurate than bf16 activations; the oracle therefore runs in fp32 too, so comparisons are tight (~1e-4 relative per activation).
  • Recurrent SSM state: fp32, mandatory (mamba_ssm_dtype: float32). Downcasting degrades quality.
  • Matmul: x @ Wᵀ — multithreaded BLAS on CPU (OpenBLAS/MKL), cuBLAS on CUDA. The decode hot path is a matrix–vector product.
  • Softmax in fp32 with max subtraction; RoPE angles fp32, cos/sin fp64; softplus linear above 20; L2 norm uses SUM.
  • M5 exception: the 27B oracle runs in bf16 (fp32 ~108 GB > RAM), so its logits use bf16 tolerance and the primary check is exact token ids.

14. Oracle methodology — how correctness was proven

oracle/ scripts oracle/README.md tests/helpers.py

Each milestone has a Python script that dumps ground truth from HF transformers (fp32, eager attention) into .npy files, and a pytest that compares the engine's trace activations against them — layer by layer, not just final text. The oracle has its own venv and requirements (torch/transformers/tokenizers). The tokenizer/chat goldens (tests/golden/) ship with the project; the activation/logit dumps (oracle/dumps/) are git-ignored (~51 MB) and regenerated with the oracle scripts (needs torch). Tests skip gracefully when weights or dumps are absent.

Tolerances: fp32 accumulation-order noise is ~1e-5 per op; expected agreement ~1e-4 relative per activation. Near-zero logits are cancellations of big dot products and need an absolute floor. Tokens, however, must match exactly — and they do (M3: 20 tokens; M5: greedy ids identical to the bf16 oracle). tests/helpers.flat flattens head-major oracle dumps to 2-D, matching the engine's layout. Self-consistency tests (test_forward.py) need no oracle: prefill must equal incremental decode.

15. CPU/GPU parity — one code path, verified

test_cpu_gpu_parity.py arrays.py

Because every module reads arrays.xp at call time, the CUDA path is the same code — only the namespace and the weight placement differ. test_cpu_gpu_parity.py runs tiny synthetic models on both backends and compares (it skips without CUDA). Verified on an RTX 4060; real 4B/27B weights exceed its 8 GB VRAM, so full-model GPU runs target larger/unified memory.

On a DGX Spark (128 GB unified memory, CUDA 13, cupy-cuda13x[ctk]) the validation procedure is: backend sanity check → synthetic parity → real-weight correctness (M1/M2 layer oracles with -device cuda, or M3/M5 greedy token ids vs the oracle dumps) → full 27B generation. The 27B model fits in fp32 in unified memory, so weights are converted once and matmul runs on cuBLAS — no per-call conversion, no page faults. Step-by-step commands: docs/HARDWARE.md.

CuPy 14 needs CUDA headers (pitfall #18)
Install the [ctk] extra — cupy-cuda12x[ctk] / cupy-cuda13x[ctk] (the requirements-cuda12.txt / requirements-cuda13.txt files include this) — or set CUDA_PATH, otherwise JIT kernels fail to compile.
