LLM Concepts, for developers

You know code. This page explains what a large language model actually computes — no ML background assumed, every formula shown, and the tricky parts made interactive. Everything here is grounded in the real Qwen3.8-27B architecture that naive-inference runs.

1. What an LLM computes

Strip away the hype and an LLM is a pure function:

$$ f(\text{token}_1, \dots, \text{token}_n) \;\rightarrow\; \text{logits} \in \mathbb{R}^{V} $$

It takes a sequence of integer token ids and returns one score (logit) per vocabulary entry — here \(V = 248{,}320\). The scores say "how plausible is each token as the next one". Text generation is just calling this function in a loop: 

ids = tokenize(prompt)
loop:
    logits = model(ids)              # the expensive part
    next   = sample(logits[-1])      # pick a token from the scores
    ids.append(next)
    until stop token or limit

Two phases matter for performance, and they behave very differently:

  • Prefill — process the whole prompt at once. Many tokens share each weight read, so this is compute-bound (matrix × matrix).
  • Decode — generate one token at a time. Each step reads all the weights to process a single token (matrix × vector), so it is memory-bandwidth-bound. For 27B in bf16 that is ~55 GB read per token. This is why decode is slow even on fast hardware, and why caching (below) exists.
Mental model
The model has no memory between calls. Everything it "remembers" about your conversation must be re-fed as tokens, or stored in explicit caches/state that the engine carries between calls. The engine's job is largely bookkeeping around one big stateless function.

2. Tokens, BPE, and embeddings

Byte-Pair Encoding

Models don't see characters or words — they see ids from a fixed vocabulary. Qwen uses byte-level BPE, the GPT-2 scheme:

  1. Pretokenize the text with a regex (contractions like 't, letter runs, single digits, punctuation, whitespace runs…). BPE never merges across these boundaries.
  2. Byte-encode: every byte becomes a printable Unicode character (space → Ġ, newline → Ċ, non-printable bytes → code points ≥ 256). This guarantees any input — emoji, CJK, binary — is representable.
  3. Merge: start with one symbol per character; repeatedly find the adjacent pair with the lowest merge rank (a learned priority list of ~247k pairs) and merge all its occurrences. Stop when no pair is mergeable.
  4. Look up each final symbol in the vocab → ids.

Example: "the" might be one token, while "Olá" becomes "Ol" + "á" (two tokens) because the accented form is rarer in training data. Frequent strings get short encodings; rare ones fall back to bytes.

Special tokens and chat templates

Some ids are matched literally in the text, outside BPE: <|im_start|> (248045), <|im_end|> (248046, also the stop token), <|endoftext|> (248044), think-block markers (248068/69), tool-call markers, etc. Conversations are serialized into ChatML: 

<|im_start|>system
You are helpful.<|im_end|>
<|im_start|>user
What is 2+2?<|im_end|>
<|im_start|>assistant
<think>
...model generates from here...

With thinking disabled, the prompt pre-fills an empty think block (<think>\n\n</think>\n\n) so the model answers directly. In multi-turn history, previous assistants' reasoning is stripped — the model re-reads only its final answers.

Qwen3.8 adds reasoning effort: reasoning_effort ∈ {xhigh (default), medium, low}. It is prompt conditioning, not a token budget: the template injects a trained-on instruction into the system turn ("think carefully, validate assumptions…" for xhigh; "keep thinking brief and focused…" for low; nothing for medium). The engine exposes it via the API field and the CLI -effort flag.

Embeddings: ids → vectors

The first model layer is a lookup table \(E \in \mathbb{R}^{V \times d}\) (here \(248{,}320 \times 5120\), ~2.5 GB in bf16 — ~5% of the model!). Token id \(i\) becomes row \(E[i]\), a \(d\)-dimensional vector. The last layer (lm_head) projects back: \(\text{logits} = h \cdot W_{lm}^\top\). In the 4B model both matrices are tied (the same tensor); in the 27B they are separate. Similar meanings end up in similar directions — that geometry is learned, not designed.

3. The transformer block

The vector \(h\) (the residual stream) flows through 64 layers. Each layer adds two corrections:

$$ h \leftarrow h + \text{Mixer}\big(\text{RMSNorm}(h)\big) $$ $$ h \leftarrow h + \text{MLP}\big(\text{RMSNorm}(h)\big) $$

The Mixer is either full attention (§4) or linear attention (§6) — that choice is the whole story of this architecture. The additive structure matters: information can skip any layer unchanged, which is what makes very deep networks trainable.

RMSNorm (and Qwen's zero-centered twist)

Normalization keeps vector magnitudes stable across layers:

$$ \text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}} \odot (1 + w) $$

Unlike LayerNorm there is no mean subtraction. And note the \((1+w)\): Qwen3.5 initializes \(w = 0\), so a fresh norm is the identity. Using plain \(w\) (LLaMA style) silently zeroes everything — pitfall #1 in our checklist. \(\epsilon = 10^{-6}\), computed in fp32.

SwiGLU feed-forward

$$ \text{MLP}(x) = W_{down}\Big( \text{silu}(W_{gate}\, x) \odot (W_{up}\, x) \Big), \qquad \text{silu}(z) = z \cdot \sigma(z) $$

Two parallel projections (5120 → 17408), one passed through silu, multiplied elementwise (the "gate" decides how much of the "up" signal passes), then projected back down. This is where most parameters and most FLOPs live. No biases anywhere.

4. Full attention

Queries, keys, values

Attention lets each token look at other tokens and pull information. Three learned projections turn \(h\) into:

  • Query \(q\): "what am I looking for?"
  • Key \(k\): "what do I contain?" (each past token advertises one)
  • Value \(v\): "what do I hand over if selected?"
$$ \text{Attention}(Q, K, V) = \text{softmax}\!\left( \frac{Q K^\top}{\sqrt{d_{head}}} + M \right) V $$

Dot product = similarity; \(\sqrt{d_{head}}\) keeps scores from saturating the softmax; \(M\) is the causal mask (\(-\infty\) above the diagonal — token \(i\) may only see tokens \(\le i\), because at generation time the future doesn't exist yet). Softmax turns each row into weights summing to 1; the output is the weighted average of values.

Multi-head and GQA

Attention runs in parallel heads — independent subspaces, each with its own q/k/v. Qwen3.8-27B: 24 query heads but only 4 key/value heads (Grouped-Query Attention): every 6 query heads share one KV head. Quality barely changes, but the KV cache shrinks 6×. Head dim is 256.

Two Qwen extras:

  • q_norm / k_norm: per-head RMSNorm on q and k before RoPE (stabilizes attention logits).
  • Output gate: q_proj is double-width; the second half of each head is a gate. After attention: \( \text{out} \leftarrow \text{out} \odot \sigma(\text{gate}) \). The layer learns how much of its attention result to write into the residual stream. (Full attention uses sigmoid; linear attention's norm gate uses silu — mixing them up is pitfall #3.)

RoPE: position by rotation

Attention is permutation-invariant — without help, "dog bites man" equals "man bites dog". Rotary Position Embedding injects position by rotating q and k vectors. Split a head's dims into pairs; pair \(i\) gets an angle proportional to position:

$$ \omega_i = \theta^{-2i/d_{rot}}, \qquad \text{angle} = \text{pos} \cdot \omega_i, \qquad \theta = 10^7 $$ $$ \begin{pmatrix} x_1' \\ x_2' \end{pmatrix} = \begin{pmatrix} \cos & -\sin \\ \sin & \cos \end{pmatrix} \begin{pmatrix} x_1 \\ x_2 \end{pmatrix} $$

The magic: \(q_m \cdot k_n\) then depends only on the relative offset \(m - n\) (rotation matrices compose). Low-index pairs rotate fast (fine local resolution), high-index pairs slowly (long-range). Qwen rotates only the first 64 of 256 dims (partial_rotary_factor 0.25); the other 192 pass through untouched. The "rotate_half" layout treats \((x_i, x_{i+32})\) as the pair — not adjacent elements.

5. The KV cache — why decode is cheap(er)

When generating token \(n+1\), the keys and values of tokens \(1..n\) are identical to what they were at step \(n\) (causality!). Recomputing them would be quadratic waste. So full-attention layers append each new token's (post-RoPE) k and v to a cache, and the new query attends over the whole cache:

$$ \text{KV bytes per token} = \underbrace{2}_{K+V} \cdot \underbrace{4}_{\text{KV heads}} \cdot \underbrace{256}_{d_{head}} \cdot \text{bytes} \cdot \underbrace{16}_{\text{full layers}} $$

fp32: 128 KB/token → 4 GB at 32k context, 32 GB at 262k. Painful — and the reason the hybrid design exists. Note the cache stores k after RoPE (position is baked in; pitfall #11).

6. Linear attention and the delta rule

From softmax to a recurrent state

Rewrite attention without softmax: \(\text{out}_t = \sum_{s \le t} (q_t \cdot k_s)\, v_s\). The dot product is linear, so regroup:

$$ \text{out}_t = q_t^\top \underbrace{\Big( \sum_{s \le t} k_s v_s^\top \Big)}_{S_t \;\in\; \mathbb{R}^{d_k \times d_v}} $$

The sum is a matrix-valued memory \(S_t\), updated recurrently: \(S_t = S_{t-1} + k_t v_t^\top\). Now generation needs no history at all — just the fixed-size matrix \(S\). Cost per token is \(O(d_k d_v)\), independent of context length. This is the family of linear attention / state-space models (Mamba, RWKV, DeltaNet…). The price: softmax's sharp, selective retrieval is gone — everything is superposed in one matrix.

The delta rule: memory that corrects itself

Plain outer-product accumulation has a bug: writing the same key twice adds the values instead of updating. The delta rule (Widrow-Hoff, 1960!) fixes it — before writing, read what the state already predicts for this key, and write only the difference:

$$ \begin{aligned} S_t &\leftarrow e^{g_t}\, S_{t-1} && \text{(decay: old memories fade)} \\ \text{kv} &= k_t^\top S_t && \text{(read current prediction)} \\ \delta_t &= \beta_t\,(v_t - \text{kv}) && \text{(the correction)} \\ S_t &\leftarrow S_t + k_t\, \delta_t^\top && \text{(write only the difference)} \\ o_t &= q_t^\top S_t && \text{(output reads the updated state)} \end{aligned} $$

\(\beta_t \in (0,1)\) is a per-token learning rate ("how much to overwrite"), \(g_t \le 0\) a per-token log-decay ("how fast to forget"). With \(\beta = 1\) and no decay, re-writing a key replaces its value exactly — an associative memory with put(key, value) semantics.

Gated DeltaNet: the full recipe

Qwen3.5's linear-attention layer wraps the delta rule with learned gates:

RMSNorm(h)→ in_proj_qkv→ causal conv1d (k=4) + SiLU→ split q,k,v→ L2-norm q,k · q/√128→ delta rule (fp32 S)→ RMSNormGated(·, z)→ out_proj

The gates come from tiny per-head projections of \(h\):

$$ \beta_t = \sigma(b_t), \qquad g_t = -\,e^{A_{log}} \cdot \text{softplus}(a_t + \text{dt\_bias}) $$
  • Decay structure: \(A_{log}\) and dt_bias are per-head learned parameters; \(g \le 0\) always, so the state never explodes. Some heads learn fast forgetting (local syntax), others slow (long-range facts).
  • Short conv: a depthwise causal conv1d (kernel 4, ~4 tokens of local context) with SiLU, applied to the concatenated q/k/v before the split. Its state is just the last 4 pre-activation inputs per channel — a shift register.
  • GVA (grouped-value attention): 16 key heads serve 48 value heads (ratio 3) — q/k are repeat-interleaved so each key head drives 3 consecutive value heads. More memory capacity without more key parameters.
  • L2 normalization of q and k (per head, \(\epsilon=10^{-6}\), note: sum not mean) keeps the writes bounded; q is additionally scaled by \(1/\sqrt{128}\).
  • Output gate: per 128-dim value head, \(y = \big(\text{RMSNorm}(o) \odot w\big) \odot \text{silu}(z)\) — norm before gate, plain \(w\) (init ones), not \(1+w\).
  • fp32 state, mandatory: the checkpoint declares mamba_ssm_dtype: float32. The state accumulates thousands of small writes; bf16's 8-bit mantissa rounds them away and quality degrades.
Verified equivalence
For long prompts the reference implementation uses a chunked formulation (UT-transform + triangular solves, parallel over chunks). naive-inference uses the simple recurrence for everything. M2 proved they agree: final states match within ~1e-5 in fp32. Same math, different schedule.

7. The hybrid architecture — best of both

Pure linear attention is cheap but fuzzy at precise retrieval ("what was the exact code in message 3?"). Pure softmax attention is sharp but its cache grows forever. Qwen3.5 interleaves them: 3 linear layers + 1 full layer, repeated. The linear layers carry the bulk of the context cheaply; the periodic full layers provide exact lookback.

8. Numerics: fp32, bf16, and quantization

IEEE fp32: 1 sign + 8 exponent + 23 mantissa bits. bfloat16 keeps the same 8-bit exponent (same dynamic range!) but truncates the mantissa to 7 bits (~3 decimal digits). Training and checkpoint storage use bf16; it converts to fp32 with a 16-bit left shift — lossless in that direction.

bf16 (16 bits)

naive-inference's policy (and why):

  • Weights are bf16 on disk, stored as uint16 bit patterns (NumPy/CuPy have no native bf16). Two regimes, chosen from the memory budget: when the model fits in fp32 on the active device, every matrix is converted once at load (fastest matmul); otherwise weights stay bf16 — on CPU as zero-copy mmap views, converted inside each matmul. A 55 GB checkpoint loads instantly.
  • Activations are fp32 — simpler and more accurate than the reference's bf16 activations; the oracle is therefore run in fp32 too, so comparisons are tight (~1e-4).
  • Recurrent state is fp32 — non-negotiable (§6).
  • Softmax in fp32 with max-subtraction, even in bf16 pipelines.

Quantization (int8/int4) goes further: store weights as small integers plus per-group scales, dequantize on the fly. It cuts the bytes read per token — the decode bottleneck — roughly proportionally. It's the standard lever for fitting big models on small machines (a 27B Q4 model is ~15 GB). naive-inference deliberately skips it: bf16 keeps the math honest while learning.

9. Sampling: from logits to a token

Greedy = argmax. Deterministic, repetitive. For creative text:

$$ p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}} $$
  • Temperature \(T\): \(T \to 0\) approaches greedy; \(T > 1\) flattens the distribution (more surprise, more errors).
  • Top-k: zero out everything outside the k highest logits, renormalize.
  • Top-p (nucleus): keep the smallest set of top tokens whose cumulative probability reaches p; renormalize. Adapts to confidence: sharp distributions keep few tokens, flat ones keep many.

10. Beyond text: thinking, MTP, vision

  • Thinking blocks: Qwen3.8 is post-trained to emit <think>…</think> reasoning before answering. It's ordinary generated text — the "reasoning" is computation bought with tokens. The chat template can pre-fill an empty block to skip it.
  • MTP (multi-token prediction): the checkpoint ships an extra 1-layer head that predicts the token after the next one. Used as a draft model for speculative decoding: propose k tokens cheaply, verify them in one target-model pass, accept the matching prefix — 2–3× speedups with identical output distribution. naive-inference ignores these weights (future exercise).
  • Vision: a 27-layer ViT-style tower encodes image patches into the same residual stream via special placeholder tokens; mRoPE gives image tokens 2-D positions (the three mRoPE streams T/H/W that collapse to identity for pure text). Also out of scope here.

11. How do you know an engine is right?

The methodology that made this project tractable — and the bridge to the implementation guide:

  1. Oracle: run the official implementation (HF transformers) on fixed prompts and dump intermediate tensors — not just final text.
  2. Compare layer by layer, activation by activation, in the same precision (fp32). A bug shows up at the exact operation that caused it.
  3. Self-consistency where no oracle is needed: prefill must equal incremental decode; cached generation must equal full re-prefill.
  4. Bit-exact checks where math is lossless: bf16→fp32 embedding rows must match the official reader bit for bit.
  5. Calibrated tolerances: fp32 accumulation-order noise is ~1e-5 per op; near-zero logits are cancellations of big dot products and need an absolute floor. Tokens, however, must match exactly.
